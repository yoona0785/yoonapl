
# 1. 业务背景

## 1.1 需求描述

1. 订单履约需要覆盖物流发货、送货上门、用户自提、虚拟发货，运营在待发货订单中选择发货方式并完成发货。
2. 订单兑换活动需要按店铺或店铺产品组配置多档赠品，不同门槛对应不同赠品及可兑换个数。
3. 同一活动内存在仅单订单兑换、单订单兑换与多订单累计同时支持、仅多订单累计三种场景，需要在同一配置分组内独立启用两种方式。
4. 多笔订单可以按同一用户、活动及店铺或产品组累计数量或金额。单笔订单不能同时用于单订单和累计兑换，需要记录订单用途并阻止重复使用。
5. 用户需要清楚区分两种方式的参与条件和奖励，通过独立订单集罐记录页查看累计、添加订单、兑换奖励；逐笔明细在底部弹层查看和移出。

## 1.3 目标结果

1. 运营可在订单列表或详情中完成四种类型的手动发货，履约信息同步至订单详情及小程序。
2. 活动配置与执行保持一致：仅执行当前勾选的兑换方式，按最高达标阶梯发放一次奖励，不叠加低档奖励。
3. 单订单与累计兑换对整笔订单互斥，兑换资格生成即锁定订单，未提单或未支付不造成重复发奖。
4. 形成可追溯链路：公域订单 → 参与明细 → 兑换记录 → 赠品资格 → 赠品订单 → 发货。

# 2. 关键业务规则

## 4.1 唯一性 / 并发性

1. 店铺配置以店铺ID唯一；产品组配置以店铺ID与产品组ID组合唯一。同一活动不能重复添加相同配置分组。
2. 同一分组、同一兑换方式内，阶梯门槛不可重复；不同分组、不同兑换方式可以使用相同门槛。
3. 同一公域订单只能归属一个用户的一种使用用途，整笔订单不得拆给不同用户、不同累计分组或不同兑换方式。
4. 已加入累计但尚未兑换的订单，需先移出累计，才可进行单订单兑换。重复加入同一订单不得增加累计值。
5. 单订单兑换成功生成赠品资格后，该订单不能再计入累计；累计兑换成功后，本次参与兑换的有效订单不能再用于单订单或其他累计兑换。
6. 同一用户、活动、配置分组的累计奖励最多兑换一次。未兑换前可继续累计冲高档，兑换后不再接受该分组的新累计订单。
7. 待发货订单提交发货时重新检查订单状态；同一订单不得重复发货。同一物流发货中，每个商品行必须且只能归属一组物流。
8. 正式系统需以事务、状态条件更新及幂等约束保护发货、订单加入/移出、累计确认、奖励生成和订单用途锁定，不能只依赖按钮禁用。

## 4.2 字段定义

### 4.2.1 订单管理—手动发货

1. 覆盖普通订单、跨境订单、赠品订单、积分订单手动发货。
2. 点击打开PC后台发货弹窗，默认选择物流发货。弹窗内切换方式保留草稿，只展示、校验、保存最终方式相关字段；取消或关闭不修改订单。

| 字段 / 操作 | 含义与填写方式 | 必填 / 默认 | 范围及限制 |
| --- | --- | --- | --- |
| 发货类型 | 单选：物流发货、送货上门、用户自提、虚拟发货 | 必填；默认物流发货 | 每次提交选择一种方式 |
| 物流公司 | 下拉单选 | 物流发货必填；默认空 | 原型选项：顺丰、中通、圆通、申通、韵达、极兔、京东物流、邮政EMS、其他；正式以物流字典为准 |
| 物流单号 | 文本输入 | 物流发货必填；默认空 | 去除首尾空格后1—50字，不允许空白值 |
| 发货商品 | 按订单商品行勾选，展示图片、名称、属性、商品金额、数量 | 物流发货必填；初始一组物流选中全部商品 | 支持全选、半选；本单全部商品完整且唯一分配 |
| 添加物流 | 新增一组物流公司、单号和商品选择 | 初始一组；新增组未选择商品 | 新增后不自动复制已有组商品 |
| 删除 / 全部删除 | 删除当前物流组或全部物流组 | 直接修改草稿 | 全删后可再次添加；无物流组不可提交 |
| 收货地址 | 读取订单地址 | 送货上门展示；只读 | 缺失显示“—” |
| 配送人员 | 文本输入 | 送货上门选填；默认空 | 最多30字 |
| 联系电话 | 文本输入 | 送货上门选填；默认空 | 填写时5—20个字符，允许数字、空格、+、括号、连字符；正式校验沿用联系电话规范 |
| 自提地址 | 文本输入 | 用户自提选填；默认空；无必填星号 | 最多200字；留空也可确认发货 |
| 发货备注 / 发货说明 | 多行文本 | 非物流方式选填；默认空 | 最多200字；虚拟发货字段名为“发货说明” |
| 确定 | 校验并执行发货 | 有效待发货订单可提交 | 成功后关闭弹窗并刷新列表/详情 |

3. 物流发货选择商品时，将该商品从其他物流组移除，避免一单商品被分配到多组；提交前仍需完整检查是否漏选或重复。
4. 送货上门、用户自提、虚拟发货默认发送本单全部商品，不展示“发货商品”区域，不填写物流公司、物流单号。
5. 确认后记录发货类型、发货时间、对应物流分组或配送/自提/说明信息。物流公司和单号可在详情汇总展示，多组物流保留各组商品关联。

### 4.2.2 订单兑换活动—公共配置

| 字段 | 含义与填写方式 | 必填 / 默认 | 范围及限制 |
| --- | --- | --- | --- |
| 活动类型 | 既有积分类型及订单金额固定赠品、商品数量固定赠品 | 沿用既有默认值 | 本次累计改造针对赠品类型 |
| 兑换订单范围—开始时间 | 订单完成时间下界，日期时间选择 | 选填；默认空 | 包含该时间点 |
| 兑换订单范围—结束时间 | 订单完成时间上界，日期时间选择 | 选填；默认空 | 包含该时间点；不得早于开始时间 |
| 兑换维度 | 统一维度、店铺维度、店铺产品组维度 | 必填；沿用已有活动选择 | 本次独立方式、多阶梯与累计配置针对店铺/店铺产品组；统一维度沿用原单订单配置 |
| 兑换方式 | 复选：单订单兑换、多订单累计兑换 | 每个店铺/产品组至少勾选一项；默认仅单订单 | 支持仅单订单、两者同时、仅累计 |
| 赠品领取有效期 | 资格发放后允许领取的天数 | 选填；默认空 | 空白表示长期有效；填写时为1—365天正整数 |

1. 订单范围说明固定为：“若配置，仅允许该时间范围内完成的订单”。
2. 只设置开始时间时限制下界，只设置结束时间时限制上界，均不填则不限制订单完成时间。范围与活动自身开始/结束时间分开维护。
3. 未勾选的兑换方式不展示、不执行，也不校验其门槛或赠品配置；数据作为草稿保留，重新勾选恢复。
4. 取消最后一个已勾选方式时恢复原勾选并提示“请至少勾选一种兑换方式”。
5. 历史未配置兑换方式标记的数据，视为启用单订单；已保存的累计启用状态保留。

### 4.2.3 店铺 / 店铺产品组阶梯配置

1. 添加店铺：只列出已有赠品池的公域店铺，支持名称搜索、勾选、全选、分页；已添加店铺不可再次选择。
2. 添加产品组：弹窗标题“选择公域店铺产品组”，搜索项为产品组名称，表格字段为勾选框、店铺名称、产品组名称、默认积分、创建时间。
   1. 仅列出启用的产品组；已添加项勾选且禁用，不能重复添加。
   2. 支持跨页保留选择、当前页全选及半选、数字分页、每页10/20/50条；无新增选择时“确定”禁用。
   3. 名称模糊搜索，搜索后回到第1页；取消不写入活动。
   4. 默认积分只作产品组信息展示，不作为赠品阶梯门槛或奖励数。
3. 添加后按“平台＋店铺”或“平台＋店铺＋产品组”分组。组标题展示店铺ID，提供添加阶梯、移除店铺/产品组；下方设置兑换方式。
4. 每种启用方式各有阶梯表格，字段统一为：活动赠品规则、赠品设置、操作。单订单行文案为“订单满X元／商品满X件，可兑N个赠品”；累计行为“累计满X元／件，可兑N个赠品”。

| 阶梯字段 | 必填 / 默认 | 范围及限制 |
| --- | --- | --- |
| 金额门槛X | 启用方式必填；新增默认空 | 大于0，最多两位小数，单位元 |
| 数量门槛X | 启用方式必填；新增默认空 | 正整数，单位件 |
| 可兑换赠品数N | 启用方式必填；默认1 | 正整数，不得超过该档不同SKU个数 |
| 赠品设置（x） | 启用方式至少配置一个SKU | x为本档不同SKU数；点击打开活动店铺赠品设置 |
| 删除 | 直接删除当前阶梯 | 不二次确认，未保存前只影响草稿 |

5. 新增店铺/产品组、增加阶梯时带入所属店铺赠品池快照；各档独立修改，不反向修改公域店铺或其他阶梯。
6. 单订单最后一档删除时移除对应分组；累计最后一档删除时，如单订单仍启用则关闭累计方式，如仅累计则保留待补充规则状态，需补充阶梯后保存。
7. 移除店铺、产品组及删除阶梯直接执行，不二次确认。保存活动后生效，取消活动草稿不影响已保存配置。
8. 批量设置可填写门槛、赠品个数，至少填写一项；只更新各分组当前启用方式的首档，空字段不覆盖，同时启用时分别更新两套首档。不修改后续阶梯及关闭方式的草稿。
9. 批量设置前整体校验，任一首档SKU数不足或产生同方式重复门槛时，整批不写入。
10. 配置区说明为“兑换取满足条件的最高阶梯。”，不再展示首档批量设置的长提示。
11. 活动店铺页复用店铺分组配置和校验；使用独立草稿，保存只修改本活动店铺及规则，不覆盖其他打开的活动编辑草稿。

### 4.2.4 活动店铺赠品设置

1. 弹窗标题“活动店铺赠品设置”，当前阶梯独立编辑。
2. 顶部提供添加赠品、批量赠送数量、批量商品活动数量、批量设置。批量只填写一项时不覆盖另一项，未填写或无商品时不可执行。
3. 添加赠品只从所属店铺赠品池选择SKU，已添加项禁用；支持全选、半选及确认，取消不写入。

| 字段 | 含义 | 必填 / 默认 / 限制 |
| --- | --- | --- |
| 赠送数量 | 用户选中该SKU后获得的件数 | 必填，红色星号；正整数；初始读取店铺池配置 |
| 库存数量 | 商品SKU库存 | 只读 |
| 商品活动数量 | 本档该SKU活动数量限制 | 选填；非负整数；空白不限制 |
| 排序值 | 赠品展示排序 | 非负整数；默认沿用池配置或0 |
| 售价 | 读取商品当前价格 | 只读；不作为用户支付的商品金额 |
| 商品名称 | 图片、名称、商品ID | 只读 |
| 属性 | 当前SKU属性 | 只读；缺失显示“—” |
| 规格数量 | SKU包装/规格数量 | 只读，与赠送数量分开 |
| 删除 | 移除本档SKU | 直接删除，不修改店铺赠品池 |

4. 保存校验至少一个SKU及数量、活动数量、排序值；回写当前阶梯。阶梯可兑换个数是否超过SKU数在活动整体保存时校验。
5. 取消不修改阶梯；保存弹窗仅更新活动草稿，活动保存后生效。店铺池后续变化不自动覆盖已保存活动快照。

### 4.2.5 小程序—订单输入及方式选择

1. 同一活动全部分组仅启用累计时，输入按钮文案为“添加订单”；其他情况沿用“立即兑换”。
2. 仅单订单：输入订单，校验后直接执行单订单兑换；仅累计且唯一匹配累计分组：输入后加入累计；同时支持：展示兑换方式底部弹层。多个可加入的累计分组时，通过下拉选择目标分组。
3. 底部弹层弹层标题“请选择兑换方式”；展示订单号及“可参与的兑换赠品活动”。

| 卡片 | 展示内容 | 按钮与状态 |
| --- | --- | --- |
| 本单兑换赠品 | 单个订单满X件/元，可兑换N个赠品 | “立即兑换赠品” |
| 店铺集罐兑换赠品 | 累计满X件/元，可兑换N个赠品；本单加入后累计Y件/元，满X件/元即可兑换 | “将本单加入累计”；已累计兑换的分组不可再次加入 |

1. 单订单展示实际最高达标档，未达标则展示最低档。累计展示本单加入后可达的最高档，仍未达标则展示最低档；加入后已达标时，进度文案为“本单加入后累计Y件/元，已达到兑换门槛”。门槛及赠品个数重点展示。
2. 底部提示：“同一订单不可重复兑换。两种方式可选的赠品可能不同，详情请咨询在线客服。”客服入口沿用既有能力，不新增真实客服接入。
3. 选择单订单兑换：成功生成奖励资格，展示兑换成功奖励弹窗，继续选择赠品、确认收货订单。
4. 选择加入累计：成功后仅提示“已加入累计”，直接进入集罐独立页并定位对应店铺/产品组，不显示奖励成功弹窗。

### 4.2.6 小程序—订单集罐记录独立页

1. 固定入口只在“兑换记录”页展示。
2. 当前已保存活动至少一个店铺或产品组启用多订单累计时才显示入口；均未启用则隐藏，不预留空位。
3. 仅列出本人已加入累计或已用于累计兑换订单的分组，未添加的分组不显示，全部订单已移出的分组隐藏。历史实际参与记录可查，不允许从历史分组兑换当前活动奖励。
4. 卡片展示：
   1. 第一行：平台、店铺、“已累计X件/元”；已兑换时展示兑换时累计值及“已兑换”。
   2. 产品组维度补充产品组名称，用于区分同店铺不同组。
   3. 下方展示各档兑换规则和订单明细入口，不展开逐笔订单。
5. 未兑换且当前活动启用累计时提供“继续添加订单”，返回订单兑换页并聚焦输入框；达到任一累计阶梯后提供“兑换赠品”。
6. 累计兑换成功后进入既有奖励成功弹窗及领取链路。用户关闭弹窗或暂未提单，仍可从兑换记录/集罐记录继续领取，不可重新兑换。
7. 已兑换卡片显示“领取赠品”或“查看订单”，按实际领取状态判断。关联一个赠品订单进入详情，多个订单沿用我的赠品—已领取列表。
8. 从兑换记录进入时返回兑换记录；从添加订单成功进入时返回订单兑换。空列表提供“去添加订单”。

### 4.2.7 小程序—累计订单明细底部弹层

1. 点击分组“订单明细（n笔）”打开底部弹层，背景保留集罐独立页。
2. 顶部展示平台、店铺，产品组维度补充产品组名称。

### 4.2.8 后台—集罐记录

#### 页面定位与记录粒度

1. 页面路径：营销中心—订单兑换—兑换数据—集罐记录。与兑换记录并列页签，不新增一级或二级菜单；原订单参与明细按订单展示的方式由集罐汇总取代。
2. 一条集罐由用户ID、活动ID、累计范围共同确定；店铺维度的范围为店铺ID，产品组维度为店铺ID＋产品组ID。同一用户在不同店铺、产品组、活动分别建罐，不合并累计。
3. 首笔订单成功加入后创建集罐并生成唯一集罐ID。仅配置累计但没有用户加入订单时，不生成空罐。

## 4.3 计算规则

1. **数量口径：**店铺维度累计有效订单商品数量；产品组维度仅统计订单中商品ID命中该组的商品数量，不计其他商品。
2. **金额口径：**店铺维度使用有效订单实付金额；产品组维度仅使用命中组商品的行实付总额。金额按分累计后以元、两位小数展示，不能用整单金额代替产品组金额。
3. **单订单阶梯：**按当前订单有效数量或金额，取不高于实际值的最高门槛，不按配置行顺序取最高档，不叠加低档。
4. **累计阶梯：**按同一用户、活动及分组中“已加入累计”且仍有效的订单求和，取最高达标档。兑换前重查订单限制、有效性、时间、归属及分组匹配。
5. 同一订单商品命中多个产品组时，单订单按配置顺序取首个达标组，再在组内取最高档；累计可加入的分组由用户选择，一笔订单只加入一个分组。
6. 数量/金额等于门槛视为达标。未达到最低档不能兑换，但满足基础条件时可以加入累计。
7. 累计兑换成功锁定本次全部有效参与订单，不仅锁定刚好凑够门槛的部分，也不保留超出门槛的可再用余额。无效订单不计入本次奖励。
8. “可兑换赠品数”统计可选的不同SKU；“赠送数量”指选中该SKU后实际发几件。例：可选1个SKU、保温杯赠送数量2，用户获得2只保温杯。
9. 达标组全部候选SKU不可领取时提示暂无可领取赠品，不自动降档。后续选择、库存占用、运费及提单校验沿用原领取规则。

| 示例 | 输入 | 结果 |
| --- | --- | --- |
| 单订单阶梯 | 满15/20/30件对应三档，本单25件 | 只获得20件档资格 |
| 累计数量 | 产品组111/222/333，三单分别6/5/9件 | 累计20件；其他商品不计入 |
| 累计金额 | 组内实付60元＋80元，订单其他商品500元 | 组内累计140元，不是640元 |
| 订单互斥 | A订单已生成单订单奖励资格，但尚未填写地址 | A不能加入累计；其他未使用订单仍可加入 |
| 累计一次 | 累计35件，最高档门槛30件并兑换 | 本次有效来源订单锁定；该分组本活动内不再累计兑换 |

## 4.4 关键联动逻辑

1. 店铺赠品池 → 活动阶梯赠品快照 → 单订单或累计校验 → 兑换资格 → 赠品选择 → 确认订单 → 发货。
2. 取消某兑换方式只影响执行范围，保留其配置；既有已发资格不回收，不重新计算已兑换奖励。
3. 加入累计记录归属当前用户、活动及选定分组，驱动小程序集罐卡片与后台参与明细；移出后两端状态、进度同步。
4. 兑换成功时一次完成：奖励记录及来源订单关联、资格快照、订单已使用标记、参与状态锁定。任一步失败不得只完成部分状态。
5. 领取成功仍按原规则：免运费提单成功或有运费支付成功；只选择赠品、只生成待付款订单不算领取成功，但不解除来源订单兑换锁定。
6. 物流/上门/自提发货 → 待收货；虚拟发货 → 已完成。后台列表“已发货”对应实际待收货状态。
7. 后台详情展示发货类型、实际物流公司/单号及配送、自提、说明信息；小程序物流弹层同步对应信息，不伪造运输节点。

## 4.5 异常处理规则

| 触发条件 | 反馈及处理 |
| --- | --- |
| 未选择兑换方式 | 保留原勾选，提示至少勾选一种兑换方式 |
| 门槛为空、非正数、数量非整数、金额超两位小数 | 阻止保存，指出分组及规则错误，保留输入 |
| 同分组同方式门槛重复 | 阻止保存或批量写入，不覆盖原值 |
| 赠品数超过本档SKU数、无赠品、赠送数量无效 | 阻止保存，要求补全配置 |
| 订单范围倒置或日期无效 | 提示范围错误，保留输入，不更新活动 |
| 配置了订单范围但订单完成时间缺失 | 不允许参与兑换或累计 |
| 产品组金额缺少行实付明细 | 提示无法核验金额门槛，不以整单金额回退 |
| 单号不存在、同号多店冲突、账号归属不符 | 提示对应原因，不生成奖励或增加累计 |
| 单号已被限制、白名单移除、订单失效 | 不允许新参与；已加入但尚未兑换时从有效进度剔除 |
| 订单已加入累计又尝试单订单兑换 | 提示先移出累计，不直接自动移出 |
| 订单已用于任一种兑换 | 不重复发奖，可引导查看原兑换记录或继续领取原奖励 |
| 累计未达标 | 不展示兑换按钮，允许继续添加和查看明细 |
| 库存/候选资格不可用 | 不锁定新的兑换结果，提示稍后再试 |
| 发货时订单非待发货 | 提示状态已变化，阻止重复提交 |
| 物流组缺公司/单号/商品，或未覆盖全部商品 | 提示对应物流组或商品分配错误，保留草稿 |
| 非物流方式有隐藏的无效物流字段 | 不参与当前方式校验 |
| 自提地址留空 | 允许发货，不提示必填错误 |
| 网络失败或保存失败 | 保留可恢复输入，提示重试；重试不得重复发奖、计数或发货 |

## 4.6 权限规则（按需）

1. 后台沿用订单管理、活动管理、兑换数据的既有访问及操作权限，不新增一级权限入口。
2. 小程序仅查询、加入、移出、兑换本人订单及本人资格，不得通过修改订单号、用户ID、记录ID访问他人数据。

## 4.7 时效与有效期（按需）

1. 订单完成时间范围包含起止点；活动非进行中不允许新增兑换或累计参与。
2. 时间统一按北京时间（UTC+8）处理，展示为YYYY-MM-DD HH:mm:ss；原型配置控件显示精度为分钟，秒级配置能力需正式组件明确。
3. 活动结束后保留历史累计与兑换记录；是否允许未使用累计在结束后补兑，不在本期新增，按当前活动状态校验禁止新增兑换。

## 5.1 状态-操作矩阵（按需）

## 5.7 状态流转（按需）

1. 单订单：输入订单 → 校验/方式选择 → 兑换成功及订单锁定 → 奖励弹窗 → 赠品选择 → 确认订单 → 免运费提单成功或运费支付成功 → 待发货。
2. 累计加入：输入订单 → 选择加入累计（仅累计唯一分组时直接加入） → 已加入累计 → 集罐独立页。
3. 累计移出：已加入累计 → 移出累计 → 已移出累计 → 进度重算 → 可重新参与。
4. 累计兑换：多笔已加入累计订单 → 最高档达标 → 兑换成功 → 有效来源订单全部已用于累计兑换 → 奖励弹窗 → 原赠品领取链路。
5. 发货：待发货 → 物流发货/送货上门/用户自提 → 待收货 → 既有确认收货 → 已完成。
6. 虚拟：待发货 → 虚拟发货 → 已完成。

# 6. 衍生需求与默认授权项

## 6.1 导出

1. 兑换数据沿用现有两个Sheet的Excel导出，两个Sheet中原“兑换订单”字段统一更名为“兑换订单号/集罐ID”。单订单填公域订单号，集罐兑换填集罐ID，其余字段及赠品订单号含义不变。

## 6.2 日志

1. 活动新建、编辑、删除、立即结束沿用操作日志；配置修改应能追溯操作人、活动及生效时间。
2. 加入累计、移出、单订单兑换、累计兑换及来源订单锁定记录用途日志。
3. 集罐日志弹窗字段：日志ID、操作人、操作描述、关联订单号、操作时间；最新记录在前。全部订单移出后日志仍可查询。
4. 发货日志记录订单号、发货类型、操作时间与操作人；正式系统保留必要的物流/商品分配快照，避免泄露到无权限端。
