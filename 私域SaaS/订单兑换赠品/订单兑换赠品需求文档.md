# 订单兑换赠品需求文档

## 1. 业务背景

### 1.1 需求描述

1. 公域平台订单可在微信小程序参与订单兑换赠品。查询来源默认包括平台接口订单与运营导入的订单白名单。
2. 公域店铺维护默认赠品池，活动可配置统一或按店铺发放规则。
3. 赠品兑换成功表示获得赠品选择资格，不等于赠品已经领取。用户选择赠品后需完成收货信息提交；有运费时还需支付成功，才算领取成功。
4. 赠品的规格、库存、重量、供应商、发货仓和运费模板由商品管理维护。

### 1.3 目标结果

1. 形成赠品商品维护、店铺配置、活动配置、公域订单验证、赠品选择、提单、支付、履约的完整链路。
2. 支持运营Excel 导入白名单订单，并通过兑换数据、审核与订单详情追溯结果。

### 1.4 本期范围

1. 商品中心：商品列表、新建/编辑、赠品类型、规格及商品服务配置。
2. 订单中心：订单列表、赠品订单详情及发货操作。
3. 营销中心：订单兑换列表、新建/编辑、公域店铺、赠品设置、订单白名单、兑换数据及兑换审核。
4. 微信小程序：订单兑换、成功弹窗、兑换记录、个人中心、我的赠品、赠品选择、确认订单、订单支付、支付结果、赠品及赠品订单详情。
5. 兑换数据双工作表 Excel 导出、兑换审核 Excel 导出、白名单导入校验与操作日志。

## 2. 关键业务规则

### 4.1 唯一性 / 并发性

1. 原型按公域订单号检查已兑换记录，接口订单、白名单订单及人工审核共享去重。命中多个同号订单时阻断，不自动选取第一条。
2. 验证通过后立即保存兑换结果：积分直接发放；赠品保存待选择资格，并标记公域订单已兑换。退出赠品选择不恢复公域订单的兑换次数。
3. 同一赠品选择资格只确认一次。确认选择时生成所选 SKU 的领取记录并占用库存；返回后继续流程复用这些记录，不再次发放或扣库存。
4. 人工审核通过前再次检查该公域订单是否已兑换，已兑换时禁止重复审核发奖。

### 4.2 字段定义

#### 4.2.1 商品管理列表

##### 页面路径

商品中心—商品管理。

##### 列表逻辑

1. 商品类型包含普通商品、跨境商品、直邮商品、赠品。

#### 4.2.2 商品新建 / 编辑

##### 页面路径

商品中心—商品管理—新增/编辑。

##### 表单逻辑

1. 基本信息：商品类型单选，包含赠品商品。
2. 价格/库存可维护划线价、成本价、库存、重量、限购。批量填写包含这五项，并应用到所有规格行。
3. 赠品的划线价格、主图非必填

#### 4.2.3 订单管理列表

##### 页面路径

订单中心—订单管理。

##### 列表逻辑

1. 赠品订单单价统一显示 `¥0.00`；数量取实际领取/下单数量；优惠统一显示“—”，不展示赠品优惠抵扣。

##### 列表交互

1. 点击详情进入对应订单详情，携带实际订单ID。

#### 4.2.4 订单兑换活动列表

##### 页面路径

营销中心—订单兑换。

##### 列表逻辑

1. 查询条件：活动类型为四种积分活动及两种赠品活动，订单金额固定积分、订单金额比例积分、商品数量固定积分、商品数量比例积分、订单金额固定赠品、商品数量固定赠品

##### 列表交互

1. 右上入口新增订单白名单。

#### 4.2.5 订单兑换新建 / 编辑

##### 页面路径

营销中心—订单兑换—新增/编辑。

##### 表单逻辑

1. 活动类型必选，六项在同一行展示：订单金额固定积分、订单金额比例积分、商品数量固定积分、商品数量比例积分、订单金额固定赠品、商品数量固定赠品；新建默认订单金额固定积分。
2. 积分活动保留统一维度、店铺维度、店铺产品组维度配置入口。
3. 赠品活动仅提供统一维度、店铺维度。
   1. 订单金额固定赠品：订单满X元，可兑换N个赠品；X大于0，最多两位小数。
   2. 商品数量固定赠品：商品满X件，可兑换N个赠品；X为正整数。
   3. N为正整数，不得超过对应配置的不同SKU数。店铺维度新增行默认1；已保存的非空值保留。
4. 统一维度直接添加赠品、规格选择及赠品明细表。添加/批量设置复用公域店铺赠品结构。
5. 店铺维度提供批量门槛、批量赠品个数、添加店铺；店铺选择弹窗支持名称搜索、勾选、分页和确认，只列出有赠品配置的店铺。
6. 店铺规则初始带入该店铺的赠品明细，在活动中编辑后形成独立配置，不覆盖公域店铺默认赠品。
7. 赠品领取有效期选填，默认空白，表示没有期限；填写时为1—365天正整数。

##### 列表交互

1. 保存校验活动名称、时间、门槛、赠品SKU、赠送数量、可兑换个数、有效期，失败保留输入。
2. 保存后生成/更新活动，并按开始、结束时间计算保存时的活动状态。
3. 取消未保存修改需确认。

#### 4.2.6 活动店铺

1. 页面路径：营销中心—订单兑换—活动店铺。
2. 添加店铺、批量规则、单店门槛及可兑换个数、赠品设置、删除，与活动新建/编辑复用同一套规则。
3. 页面使用独立编辑草稿；保存只更新该活动店铺及规则，不覆盖其他打开的新建/编辑页面，也不修改公域店铺默认赠品。
4. 取消需确认放弃未保存修改；顶部不重复展示活动类型/兑换维度说明。

#### 4.2.7 公域店铺列表

##### 页面路径

营销中心—订单兑换—公域店铺。

##### 列表逻辑

1. 列表字段：新增赠品数；赠品数按配置SKU行数统计。

##### 列表交互

1. 行内操作：新增赠品设置
2. 点击赠品数或赠品设置打开赠品配置。

#### 4.2.8 公域店铺赠品设置及商品选择

1. 赠品设置弹窗只维护SKU及其赠送数量、商品活动数量、排序值。
2. 明细表字段：赠送数量（红色必填星号）、库存数量、商品活动数量、排序值、售价、商品名称、属性、规格数量、操作。
3. 赠送数量为正整数，默认1；商品活动数量选填，留空表示不限制，填写时为非负整数；排序值为非负整数，默认0。
4. 批量设置仅包含赠送数量、商品活动数量。
5. 添加赠品先打开商品选择弹窗，再打开规格选择弹窗；按商品+规格标识去重，同一商品可选择多个不同规格。
6. 商品选择支持名称、类型、商品ID、品牌、SPU、分类、创建方式、商品状态条件及分页；只加入赠品类型商品。已加入规格不可重复添加。
7. 配置阶段可查看下架/无库存商品；实际兑换及领取时检查上架和可用库存，不因已配置而免除校验。
8. 保存所选规格后返回明细表。

#### 4.2.9 订单白名单

##### 页面路径

营销中心—订单兑换—订单白名单。

##### 列表逻辑

1. 查询条件：订单号模糊、兑换状态（全部/未兑换/已兑换）。
2. 列表字段：订单号、平台/店铺、订单金额、订单完成时间、订单商品、兑换状态、操作。
3. 订单商品点击弹窗展示商品ID、商品名称、下单数量。
4. 操作仅移除白名单。
5. 右上角可查看操作日志、下载模板、导入订单。

##### 列表交互

1. 下载模板为一个 `.xlsx` 文件，两个工作表：
   1. 订单维度：平台、店铺ID、订单号、订单完成时间、订单金额。
   2. 商品维度：订单号、商品 ID、商品名称、下单数量。
2. 两表一次上传，按订单号关联；订单维度订单号唯一，一订单可有多条商品明细。同号多店铺不能在同批中歧义关联。
3. 表头按字段和顺序校验，忽略标题内空白及末尾空白列；实际缺列、错列或多余非空表头提示预期/实际表头。
4. 平台、店铺ID须匹配现有店铺；订单金额非负且最多两位小数；完成时间支持Excel日期或北京时间文本，不可晚于当前时间；商品ID、名称必填，下单数量为正整数。
5. 文件须为.xlsx，不超过10MB；单次最多5000个订单、20000条商品明细。不接受加密工作簿和公式结果未转为值的单元格。
6. 保留文本ID前导零；过长数值型订单号/商品ID拒绝，提示改用文本。
7. 校验重复订单、重复商品、缺明细、孤立明细、字段冲突；错误订单整单不进入待导入集合。相同已导入数据跳过，冲突或已兑换订单不覆盖。
8. 校验预览显示可导入数、重复数、错误数以及工作表/行号/原因。用户点击确认导入后才写入完整有效订单；取消不导入。
9. 移除白名单需确认，移除后从名单列表和白名单校验中排除，不回收既有兑换及赠品订单。
10. 操作日志弹窗展示时间、操作人、操作类型、内容；记录模板下载、导入校验/失败、确认导入及移除白名单。当前实现未提供错误文件下载入口。

#### 4.2.10 兑换数据

##### 页面路径

营销中心—订单兑换—兑换数据。

##### 列表逻辑

1. 列表字段：新增兑换赠品。
2. 兑换赠品展示领取状态和“赠品详情”，无赠品显示“—”；可出现未领取、已领取、已失效。
3. 赠品详情弹窗字段：商品名称（图片、名称、ID）、属性、规格数量、赠送数量、订单号。未选赠品时可查看候选池；已选择时展示实际领取记录，未建单订单号为“—”。

##### 列表交互

1. 赠品详情中点击关联订单号进入后台赠品订单详情。

#### 4.2.11 兑换审核

##### 页面路径

营销中心—订单兑换—兑换审核。

##### 列表逻辑

1. 待审核不展示已发奖励；通过为积分时显示“+N 积分”和兑换店铺；通过为赠品时仅显示“赠品未领取/赠品已领取”和兑换店铺；驳回显示意见。
2. 已通过赠品的领取状态由真实领取/支付结果计算，不以审核通过代替领取成功。
3. 待审核提供审核入口；已审核可查看只读详情。

##### 列表交互

1. 赠品审核弹窗按以下顺序展示：
   1. 申请信息：下单平台、申请店铺名称、申请人/手机号、用户ID、申请活动及ID、提交时间、补充说明、订单截图。
   2. 审核结果：通过/驳回单选，默认通过。
   3. 通过时选择兑换店铺，自动带出该店铺配置的赠品；表格展示商品名称、属性、规格数量、赠送数量、操作。
   4. 审核意见最多200字符，通过选填、驳回必填；底部取消、确定。
2. 切换店铺立即更新赠品列表，保留已填意见；提交前不改写原申请。申请店铺与实际兑换店铺分别保存。
3. 通过时需选有效店铺且至少存在可领取赠品，保存店铺赠品池快照，生成待选择资格，不立即扣减候选池全部商品库存。
4. 用户之后按资格上限选择赠品；上限优先取对应活动配置，缺失时按最多可领处理，并不超过赠品SKU数。
5. 通过前检查订单未兑换；重复审核不重复发奖。已审核详情只读，按审核时保存的赠品配置回显。
6. 有订单截图时可点击放大，无图显示暂无订单截图，不生成模拟凭证图片。
7. 驳回意见未填写时阻止提交；取消不保存。

#### 4.2.12 小程序订单兑换及成功弹窗

##### 页面路径

微信小程序—订单兑换。

##### 页面逻辑

1. 输入公域订单号后点击立即兑换，校验订单限制、是否已兑换、候选订单是否唯一、活动状态、店铺、完成时间、奖励门槛及兑换次数；赠品还校验存在可领取SKU。
2. 赠品成功弹窗：兑换成功、可从候选赠品选择N个、赠品及赠送数量、温馨提示、选择并领取赠品；点击进入赠品选择。
3. 关闭成功弹窗不撤销已发积分或赠品资格。未完成赠品流程可通过我的赠品/兑换记录继续。

#### 4.2.13 小程序兑换记录

##### 页面路径

订单兑换—兑换记录。

##### 页面逻辑

1. 页签为全部、兑换成功、兑换失败；记录按时间倒序展示。
2. 卡片展示平台、店铺、结果、奖励类型、兑换订单、奖励数量及时间。
3. 赠品未选择、已选择但未提单、已提单但未付运费，都显示点击领取；完成免运费提单或运费支付后显示查看订单。
4. 失败记录展示提交订单号、失败原因和时间，不展示已发奖励。

##### 页面交互

1. 点击领取进入我的赠品—赠品选择。已选内容保留；未建单继续确认订单，有待付款订单继续原单支付。
2. 查看订单：只关联一个赠品订单时直接进入赠品订单详情；关联多个赠品订单时进入我的赠品—已领取列表。

#### 4.2.14 个人中心及我的赠品

##### 页面路径

微信小程序—个人中心—我的赠品。

##### 页面逻辑

1. 我的赠品保留全部、待领取、已领取、已失效筛选；从个人中心进入默认全部。待选择赠品归入全部及待领取。
2. 未完成选择、提单或运费支付的资格展示待选择赠品及选择赠品入口。
3. 已领取卡片展示图片、名称、属性/规格、数量和查看订单。
4. 可领取的历史独立资格卡片保留立即领取入口，不额外显示“待领取”字样；可显示有效期或长期有效。当前新兑换流程优先使用待选择资格入口。
5. 已失效赠品保留商品信息，内容置灰并显示“已失效”印章，禁止领取。待选择资格到期时显示失效，不开放继续选择。
6. 全部为空时展示插画及去兑换赠品入口；单状态为空展示对应状态无赠品。

##### 页面交互

1. 选择赠品进入选择页；未建单继续确认订单，有待付款订单继续支付。
2. 已领取商品点击或查看订单进入赠品订单详情；未领取商品详情使用同一套卡片风格，展示赠品信息并保留立即领取，失效时禁用。
3. 已发货可通过物流入口查看物流。

#### 4.2.15 赠品选择

1. 页面路径：我的赠品—赠品选择，也可由兑换成功弹窗、兑换记录点击领取进入。
2. 首次选择展示该次兑换保存的候选SKU、商品图片/名称、属性、赠送数量、可选N个说明和已选数量。
3. 最少选择1个、最多N个不同SKU。达到上限后其他未选项禁用；无库存、已下架或活动数量不足的SKU不可选择。
4. 确认领取再次校验资格有效期和库存，生成所选领取记录并占用对应SKU数量，然后进入确认订单。
5. 已确认选择但未完成提单/支付时，重新进入展示原选择，不再分配第二批赠品；确认后继续确认订单或原单支付。
6. 选择页返回不删除资格、不重复恢复已占用库存；尚未确认的勾选不视为领取成功。

#### 4.2.16 确认订单

1. 页面路径：我的赠品—赠品选择/立即领取—确认订单。
2. 页面模块：收货地址、赠品商品信息、费用明细、订单备注、购买须知、底部总计及提交订单。
3. 商品展示图片、名称、规格、金额 `¥0.00` 及数量。数量默认该资格赠送数量，步进范围为1至该资格数量，不能超过已分配数量。
4. 费用明细展示商品原价 `¥0.00`、运费、订单备注。运费按所选SKU商品运费相加。
5. 提交时再次验证资格未领取/未失效及地址完整。失败保留输入，不重复创建订单。
6. 运费为0：生成待发货订单并进入成功页；运费大于0：生成待付款订单并进入订单支付页。

#### 4.2.17 支付及结果

1. 页面路径：确认订单—订单支付—支付结果，或免运费提单直接到支付结果样式的成功页。
2. 支付页展示实际待付运费、订单编号及支付方式。

#### 4.2.18 小程序赠品及订单详情

1. 已领取赠品订单详情按最终参考图展示：订单状态、物流摘要、收货信息、商品明细、应付合计、商品总额、运费、订单信息及底部操作。
2. 商品明细显示名称、图片、属性、实付0元和实际领取数量；订单信息含订单编号、下单、支付、发货、完成时间及备注，缺失时间为“—”。
3. 收货手机号在该详情中脱敏；订单编号可复制。物流弹窗展示已有运单及节点。
4. 待付款显示支付运费；待收货/已发货显示查看物流、确认收货；已完成显示查看物流、去评价/查看评价；其他状态提供我的赠品入口。
5. 确认收货需确认，成功后记录完成时间。评价仅已完成订单可提交，保存后可查看，不能重复评价。
6. 未领取商品详情展示赠品信息、领取有效期、赠送数量和费用；立即领取进入确认订单，已失效时禁用。

### 4.3 计算规则

1. 积分计算使用订单实付金额或订单商品下单数量，按活动类型区分：

| 活动类型 | 计算方式 |
| --- | --- |
| 订单金额固定赠品 | 金额达到门槛，获得最多选择N个SKU的赠品资格 |
| 商品数量固定赠品 | 商品数量达到门槛，获得最多选择N个SKU的赠品资格 |

1. 可兑换赠品个数统计不同SKU，不是赠送总件数。例如可选1个SKU，所选SKU赠送数量为2，则用户获得该SKU 2份。
2. 规格数量为商品规格本身的包装/数量字段，与赠送数量分别展示；SKU去重键为商品ID+规格。
3. 赠品领取成功统一定义：无运费时提单成功且订单待发货；有运费时支付成功且订单进入后续履约状态。仅选择赠品或仅生成待付款订单均为未领取。
4. 赠品订单商品总额、原价及实付商品金额按0元展示，优惠为“—”。订单应付为运费。
5. 领取时间：免运费取提单时间，有运费取支付成功时间。未领取记录留空。
6. 有效期留空时不生成到期时间，显示长期有效；填写D天时以兑换/审核发放时刻加D天保存快照，不因后来修改活动而回改。
7.  库存占用发生在用户确认所选SKU时，按赠送数量扣减；初始发放候选池资格及赠品审核通过不扣减候选池全部库存。

### 4.4 关键联动逻辑

1. 自动兑换：商品/店铺配置 → 活动规则 → 用户输入订单 → 校验成功并标记已兑换 → 积分成功弹窗或赠品成功弹窗。
2. 赠品领取：成功弹窗/我的赠品/兑换记录 → 赠品选择 → 确认订单 → 免运费成功，或待付款 → 支付成功 → 成功页 → 订单详情。
3. 中途退出：未提单/未支付 → 我的赠品仍为待选择 → 恢复原选择 → 继续原提单/支付；不重新发奖、扣库存或建单。
4. 人工审核：待审核 → 积分通过直接发积分；赠品通过保存所选兑换店铺赠品池及限选数 → 用户按同一领取链路继续；驳回保存原因，不发奖励。
5. 配置快照：公域店铺默认赠品变更不覆盖已保存的活动独立配置；活动编辑不回改已发资格；已审核赠品详情读取审核时配置。
6. 同步状态：领取结果驱动我的赠品、兑换记录、兑换数据、审核列表；发货、确认收货和评价更新赠品订单。
7. 多订单查看：兑换记录关联一个赠品订单直接查看；多个进入我的赠品—已领取列表。
8. 订单限制优先于兑换资格校验。两个来源同号或来源冲突不静默合并。

### 4.5 异常处理规则

| 场景 | 页面处理 |
| --- | --- |
| 订单号为空 | 提示请输入单号进行兑换，不新增兑换记录 |
| 未找到订单 | 提示核对订单号，记录失败尝试用于兑换失败页签 |
| 已兑换 | 阻止再次发奖；存在未选赠品资格时可恢复选择，否则提示查看兑换记录 |
| 同号多个订单 | 提示核对平台和店铺，不自动取首条 |
| 活动状态、店铺、完成时间、门槛或次数不符 | 提示具体原因，不发奖励 |
| 无可用赠品/库存不足 | 阻止确认，保留资格和已填信息，不提示领取成功 |
| 超过SKU选择上限 | 限制继续勾选，提示最多选择N个 |
| 领取资格已失效 | 展示失效状态，禁止新选择/新提单 |
| 收货信息不完整 | 提示并打开地址编辑，不提交订单 |
| 未同意购买须知 | 提交按钮禁用 |
| 重复审核/提单/支付 | 读取已有状态，不重复创建奖励或订单 |
| 驳回无意见 | 阻止提交，提示填写审核意见 |

### 4.6 数据来源

1. 公域订单来源为预置接口订单或确认导入的白名单；审核材料来自已有申请记录，缺失图片/物流不补造。


## 5. 状态与异常

### 5.1 业务状态

1. 我的赠品筛选：全部、待领取、已领取、已失效；待选择属于待领取范围。
2. 赠品订单：待付款、待发货、待收货、已完成、已关闭；后台已发货页签对应待收货。
3. 白名单：页面仅区分未兑换/已兑换，移除后不在列表展示。


### 5.2 状态-操作矩阵

| 对象状态 | 页面操作 | 结果/限制 |
| --- | --- | --- |
| 活动待开始 | 编辑、复制、删除、推广、日志；赠品店铺维度可进活动店铺 | 统一维度不显示活动店铺 |
| 活动进行中 | 编辑、复制、立即结束、推广、日志；符合条件展示活动店铺 | 结束不回收已发资格 |
| 活动已结束 | 复制、删除、推广、日志；赠品店铺维度可进活动店铺 | 不重新开启当前兑换 |
| 审核待审核 | 通过/驳回、选择相应奖励、填意见 | 只发一种奖励 |
| 审核通过/驳回 | 只读详情、日志 | 通过赠品显示实际领取状态 |
| 赠品未选择 | 选择赠品 | 确认后生成所选资格并占用库存 |
| 已选择、未提单 | 仍显示待选择，恢复选择/确认订单 | 不再次扣库存 |
| 有运费、未支付 | 仍显示待选择，恢复原单支付 | 不重复建单，不算已领取 |
| 免运费提单成功/运费支付成功 | 查看订单，进入已领取 | 已关联一个订单直达详情，多个到已领取列表 |
| 赠品已失效 | 查看信息及失效标志 | 禁止新领取 |
| 订单待付款 | 支付运费、查看详情 | 支付成功后待发货及成功页 |
| 订单待发货 | 用户查看；后台备注、发货 | 发货后待收货 |
| 订单待收货/已发货 | 查看物流、确认收货 | 确认后已完成 |
| 订单已完成 | 查看物流、去评价/查看评价 | 不重复提交评价 |
| 导入校验完成 | 确认导入、取消 | 仅导入有效完整订单 |
| 白名单已兑换/未兑换 | 查看商品、移除 | 移除不撤销已发奖励 |

### 5.3 状态流转

1. 积分：输入订单 → 验证通过 → 标记兑换成功/发放积分 → 成功弹窗 → 我的积分。
2. 赠品：输入订单 → 验证通过 → 标记兑换成功/创建待选择资格 → 成功弹窗 → 赠品选择 → 确认订单。
3. 免运费：确认订单提交 → 待发货/领取成功 → 成功页 → 订单详情。
4. 有运费：确认订单提交 → 待付款/仍未领取 → 支付成功 → 待发货/领取成功 → 成功页。
5. 中断：未提单或未支付 → 我的赠品待选择 → 恢复所选内容或原支付订单；不重新验证兑换或重复扣库存。
6. 审核：待审核 → 驳回（不发奖励），或通过 → 积分发放/待选择赠品资格 → 与自动兑换共用后续流程。
7. 履约：待发货 → 后台发货 → 待收货 → 确认收货 → 已完成 → 评价。

## 6. 衍生需求与默认授权项

### 6.1 导出

1. 兑换数据：当前筛选全量结果导出 `.xlsx`，文件名 `兑换数据_YYYY-MM-DD.xlsx`，包含两个工作表。
   1. sheet1字段顺序：活动名称、活动ID、用户ID、用户昵称、兑换订单、兑换积分、积分发放时间、赠品状态、赠品领取时间、兑换店铺、电商平台。
   2. sheet2字段顺序：兑换订单、兑换店铺、电商平台、赠品名称、赠品ID、属性、规格数量、赠送数量、订单号。
   3. sheet1每条兑换一行；sheet2按实际SKU/领取记录展开，尚未选择时沿用当前赠品详情的候选池快照。积分记录不生成赠品明细行。
   4. 赠品奖励兑换积分为0，积分发放时间留空；无赠品的赠品状态为“—”。未领取时间留空，已领取取提单/支付时间。
2. 兑换审核：当前筛选全量结果导出 `.xlsx`，文件名 `兑换审核_YYYY-MM-DD.xlsx`，单工作表“兑换审核”。
   1. 字段顺序：下单平台、店铺名称、提交单号、补充说明、活动ID、用户昵称、用户ID、提交时间、截图、审核时间、审核结果、兑换积分、赠品状态、兑换店铺、关联产品组。
   2. 下单平台/店铺名称取原申请店铺，兑换店铺取审核实际选择，不混用。
   3. 只有审核通过的积分奖励填写实际积分，其他为0；审核通过的赠品填写已领取/未领取，其他为“—”。
   4. 截图导出链接，多张按换行分隔；关联产品组导出实际记录的组名称，未关联留空，不根据店铺全部产品组推断。
3. Excel冻结首行、设置列宽和筛选，ID保留文本，积分及数量为数值，时间列使用日期格式。导出无数据时提示，不下载空数据文件。
4. 商品及订单原有导出入口保持各自范围，不强行套用上述两类字段；当前原型基础导出仍采用CSV，商品导入修改也使用CSV，不代表全部文件功能已统一成Excel。
